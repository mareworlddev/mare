# Dispatching Parallel Agents

Parallel work can accelerate broad research, but delegation is optional and never overrides the partner's instructions, platform rules, permissions, privacy limits, or resource constraints. Use agents only when delegation is authorized and a suitable capability is available. Otherwise do the work in the current session; never pretend agents were used.

## Decide whether to parallelize

Divide a topic into independent questions only if their inputs are available, the outputs can be combined, and the work will not interfere through shared state. Work sequentially when later questions depend on earlier answers, the topic needs a single coherent investigation, or parallelism costs more than it saves.

## Delegate and synthesize

1. Define each question and its boundary. For example, compare a market's customer needs, competitors, and regulatory context in separate research tasks.
2. Give each agent a self-contained brief: goal, relevant context, scope, constraints, available sources, evidence requirements, expected output, and deadline or resource limit if applicable. Do not disclose unnecessary confidential information.
3. Dispatch eligible tasks concurrently using the platform's supported capability. Track each task and its status. Do not launch external tools or additional sessions to bypass a restriction.
4. Review each result and inspect relevant primary sources when available. Distinguish sourced facts from inference, check dates and contradictions, and investigate gaps. Resolve overlapping claims before combining results.
5. Synthesize the findings into one answer tied to the original question, with sources, uncertainty, and any missing work. Use `verification-before-completion` before asserting completion.

If an agent fails or returns weak evidence, retry only when permitted and worthwhile, investigate directly, or disclose the gap. A summary from an agent is not independent verification.
